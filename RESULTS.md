# Results

These measurements replace the earlier experiment set. The scoring function,
training procedure, and operator counts changed, so the old error values are
not directly comparable. The six source JSON files are committed in `results/`.

## Settings and models

Each configuration has ten independent runs (seeds 370–379), a fixed
20,000/5,000 split (seed 370), and 50 evaluated generations. All training rows
are used each generation. Settings differ only in population or size penalty
within each dataset. The defaults are population 250 and penalty 0.01.

| Dataset | Selected baseline model | Held-out error | Held-out RMSE | Tree nodes |
|---|---|---:|---:|---:|
| dataset1 | `13.99997085 + 0.999976112 * ((x * (x - 5)) - x)` | 1.66457e-06 | 0.0242904 | 7 |
| dataset2 | `6.665645961e-11 * (((x1 / x3) / x3) * x2)` | 0.0015837 | 1.29674e+07 | 7 |

The first model is approximately `x² - 6x + 14`. The second has the
inverse-square form `G*x1*x2/x3²` for positive recorded distances, consistent
with the form of Newton's gravitational law. These are inferred explanations
of the data, not externally verified generating formulas. Protected division
means algebraic simplifications need special care at zero divisors.

Eight baseline dataset1 runs returned seven-node trees; the other two returned
nine-node trees with the same quadratic shape. Nine baseline dataset2 runs
returned seven-node inverse-square trees. The remaining run returned an
11-node expression with extra terms and slightly lower raw held-out error.
The size penalty selected a seven-node model as the overall winner.

## Population and complexity comparisons

The table is generated by `run.summarize` from the six saved files. "Selected"
means lowest held-out error multiplied by `1 + penalty * size`; it need not
be the model with the smallest unpenalized error. Dataset1 error is normalized
MSE; dataset2 error is mean squared relative error with denominator floor 0.005.
The two datasets' error values should not be compared with each other.

| Dataset | Population | Penalty | Selected test error | Median test error | Median nodes | Mean diversity, initial → final |
|---|---:|---:|---:|---:|---:|---:|
| dataset1 | 250 | 0.01 | 1.66457e-06 | 1.66457e-06 | 7 | 88.3% → 17.3% |
| dataset1 | 250 | 0 | 1.66457e-06 | 1.66457e-06 | 44 | 88.3% → 62.0% |
| dataset1 | 50 | 0.01 | 1.66457e-06 | 1.66457e-06 | 9 | 92.6% → 39.6% |
| dataset2 | 250 | 0.01 | 0.0015837 | 0.0015837 | 7 | 89.8% → 22.9% |
| dataset2 | 250 | 0 | 0.00136849 | 0.00157769 | 57 | 89.8% → 60.9% |
| dataset2 | 50 | 0.01 | 0.0015837 | 0.129975 | 6 | 96.6% → 22.6% |

For a descriptive accuracy count, call a run baseline-level when its held-out
error is at most 1.02 times its dataset's selected baseline error, including
runs that score better. This measures comparable prediction error, not exact
formula recovery or a proven rounding-noise floor.

- Population 250 with penalty 0.01: 10/10 baseline-level runs on each dataset.
- Population 50 with penalty 0.01: 8/10 on dataset1 and 5/10 on dataset2.
- Population 250 with no penalty: 10/10 on each dataset.

The smaller population uses one fifth as many individual evaluations per run
(2,500 versus 12,500), but is less reliable in these experiments. All runs have
the same generation budget; their generation counts do not measure different
early-stop thresholds. This is evidence for using population 250 here, not a
claim that it is optimal for other problems.

Removing the penalty increased median returned tree size from 7 to 44 nodes
on dataset1 and from 7 to 57 nodes on dataset2. Dataset1's held-out error stayed
approximately the same. Dataset2's selected unpenalized model scored better
(0.00136849) but used 57 nodes. A lower error alone does not establish that its
additional terms have a useful physical interpretation. The complexity penalty
expresses our preference for a smaller model; it does not prove which model
created the data.

## Convergence and diversity

In the baseline dataset1 runs, raw training error first came within 2% of the
returned model's error at generations 0–4. For dataset2, nine runs reached that
level at generations 3–4 and one reached it at generation 41. This describes
prediction accuracy, not when the final compact tree was found. Every run still
continued through generation 49.

Diversity is the fraction of distinct expression strings, averaged over all ten
runs. It counts syntax: two different trees may compute the same function.
At the baseline settings it fell from 88.3% to 17.3% on dataset1 and from 89.8%
to 22.9% on dataset2. Initialization and mutation did not prevent that decline.
Without a size penalty, final diversity was higher (62.0% and 60.9%), alongside
larger trees. These observations show an association between the settings,
size, and diversity; they do not isolate a single cause of search failures.

## Limits and reproduction

All 25,000 rows remain included. Dataset2 has 13 recorded zero-distance rows,
including three in the held-out split. The arithmetic uses protected division
there. Its relative-error denominator also retains zero-valued targets.
Rounding can obscure the underlying measurements, but the measured errors are
not proven lower bounds. The large dataset2 RMSE is retained in the JSON and
model table; it reflects absolute errors that the relative metric weights
differently.

Scale constants and dataset1's normalization variance are fitted on training
data only. The held-out set selects the winner across runs and supports the
parameter comparisons, so it is not an independent final evaluation of a
selection process. Ten runs and one split provide limited evidence about
reliability. Dataset3 was not attempted.

Run the six commands in [README.md](README.md) to regenerate the experiments.
Each JSON records the seeds, dataset hash, full-precision constants, training
and held-out errors, history, Python/NumPy versions, and elapsed time. Timings
were collected while configurations ran concurrently and should not be treated
as a controlled speed benchmark. Numerical details can vary across dependency
versions; elapsed times will vary across executions. To regenerate the table:

```sh
python -c 'from pathlib import Path; import run; print(run.summarize(Path("results").glob("*.json")))'
```

Add `--plot` to any experiment command to regenerate its three-panel figure.
The plots show the training error of the generation's penalized winner, mean
tree size, and distinct expression count.
